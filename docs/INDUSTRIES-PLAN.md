## 2. 실제 DB와 회사 식별 범위

조사 시점에 테이블은 `salary_data`, `salary_dart_sources` 두 개입니다.

| 테이블 | 주요 컬럼·키 | 용도 |
|---|---|---|
| salary_data | id BIGINT UNSIGNED PK, company_name VARCHAR(255), fiscal_year SMALLINT, employee_name VARCHAR(255), position_name VARCHAR(255), compensation BIGINT NULL | 원 단위 공시 보수. 회사명 및 연도 인덱스 |
| salary_dart_sources | fingerprint CHAR(64) PK, salary_id, corp_code CHAR(8), fiscal_year, rcept_no, source_unit, raw_json, changes_json, package_sha, imported_at | 보수 행에 대한 DART 회사 식별과 원문·정제 근거 |

연도별 건수는 2021년 5,198건, 2022년 5,426건, 2023년 5,540건, 2024년 2,584건, 2025년 2,671건으로 총 21,419건입니다. 2024·2025년 5,255개 행은 DART 고유번호에 연결돼 있지만 2021~2023년에는 이 연결이 없습니다. `salary_data` 자체에는 종목코드가 없습니다.

DART 고유번호를 회사의 기본 식별자로 사용하고 종목코드를 보조 식별자로 저장합니다. 이름은 표시 및 후보 탐색에만 사용합니다. 명칭 변경 전후의 회사가 같은 고유번호이면 하나의 법인으로 집계합니다. 이름이 같은 다른 법인은 고유번호가 다르면 구분합니다. 하나의 보수 행에 서로 다른 고유번호 근거가 충돌하면 자동 포함하지 않습니다.

기존 자료에는 약식 표기와 현재 표기가 섞여 있습니다. 예를 들어 기존 순위 목록의 `KB증권`, `IBK투자증권`, `유진투자증권`과 신규 공시의 `케이비증권`, `아이비케이투자증권`, `유진증권`을 단순 문자열 일치만으로 묶으면 누락될 수 있습니다. 새 조회는 고유번호로 연결하므로 이 문제를 줄입니다.

## 3. 추가 DB 설계

SQL은 `migrations/001-industries.sql`입니다. 기존 두 테이블은 ALTER·DELETE·TRUNCATE하지 않습니다.

| 신규 테이블 | 핵심 설계 |
|---|---|
| industry_categories | 업권 코드 PK, 고유 slug, 명칭, 부모 코드, 설명, 정렬 순서, 페이지 공개 여부 |
| industry_companies | DART 고유번호 PK, nullable 고유 종목코드, 정식명·표시명, KSIC 코드, 출처·확인일 |
| company_industries | 회사·업권·적용 시작연도 복합키, 종료연도, 주력 여부, pending/approved/rejected, 분류 근거 JSON |
| salary_company_links | 기존 보수 행 ID PK, 회사 고유번호, 승인 상태, 연결 방법과 근거 JSON |

공개 기본 분류는 요청한 20개이며, 금융 세분화를 위해 비공개 부모 노드 `FINANCE`를 둡니다. 나중에 생명보험·손해보험·은행·금융지주 등 하위 업권을 추가할 수 있습니다. 주력 업권의 적용 기간 중복은 검증기와 적용 도구에서 차단합니다. 종목코드가 다른 법인과 충돌하면 자동 연결하지 않습니다.

회사 분류가 없는 상태는 미분류로 관리합니다. `pending` 분류는 후보일 뿐 순위에 포함하지 않습니다. `salary_company_links`는 과거 공시와 대조한 행을 개별 승인하는 데 사용할 수 있으며 회사명 일괄 연결을 자동 실행하지 않습니다.

2024년 이후에는 `salary_dart_sources`의 고유번호 연결도 조회 시 직접 해석합니다. 따라서 승인된 기업의 새 연도 자료는 별도 행별 연결 작업 없이 반영됩니다. 승인된 명시적 행 연결이 있다면 이를 우선하며, 그렇지 않으면 충돌 없는 DART 출처를 사용합니다. 캐시 갱신 시간은 최대 15초입니다.

이번 증권 후보 30곳은 DART 고유번호를 먼저 확보하고 기업개황 API로 각각 확인했습니다. 27곳은 KSIC 66121로 확인돼 증권 분류를 승인했고, 다올투자증권(661)·아이비케이투자증권(6612)은 추가 사업 검토가 필요합니다. 한국증권금융(6499)은 증권 중개업으로 승인하지 않고 기타금융 후보로만 남겼습니다. 실제 공시 법인의 고유번호·종목코드·업종코드·확인일·응답 체크섬은 `data/industry-companies.json`에 있습니다. 이는 국내 모든 증권사를 망라하는 명단이 아닙니다.

공식 근거: [OpenDART 고유번호·기업개황 가이드](https://opendart.fss.or.kr/guide/main.do?apiGrpCd=DS001), [DART 기업개황 안내](https://dart.fss.or.kr/guide/contents130.jsp), [통계청 KSIC 분류 자료](https://kostat.go.kr/boardDownload.es?bid=108&list_no=422598&seq=3). 세부 코드 근거는 기업별 기업개황 응답에 기록했습니다.

## 5. 증권 페이지 구현 내용

- `/industries`: 20개 업권 안내 카드. 증권만 링크를 공개하고 나머지는 분류 검토 중으로 표시합니다.
- `/industries/securities`: SSR HTML로 즉시 최신 연도의 상위 20건, 기업별 공시 건수·최고액, 설명을 표시합니다.
- 상세 검색: 이름·회사명/종목코드·직위·연도를 동시에 적용하며 승인된 증권 법인 안에서만 검색합니다.
- 연도: 식별이 연결된 실제 자료의 연도만 표시합니다. 현재 2024·2025년입니다. 그 외 연도 요청은 설명이 있는 400 응답을 반환합니다.
- 순위: 공동 순위, 회사별 지급 내역 분리, 원 단위 구분 기호, 금액 검토 대상 제외를 적용합니다.
- 상세 목록: 페이지당 20건입니다. CSV는 현재 필터의 전체 페이지 결과를 내려받습니다.
- 링크: 보수표 회사명은 기존 전체 검색으로 이동하고 검색을 자동 실행합니다. 인물명은 업권 내 이름 검색으로 연결됩니다. 익명 이름에는 인물 링크·기사 링크를 만들지 않습니다.
- SEO: 고유 title·description·H1, canonical, 업권 내부 링크와 사이트맵을 제공합니다. 필터·페이지 이동·빈 자료는 noindex 처리하고 CSV도 noindex 응답을 보냅니다.
- 모바일: 표는 가로 스크롤하고 금액은 줄바꿈하지 않습니다. 스크롤 영역·입력·표 헤더에 접근성 속성을 제공합니다.

DB 승인 전에도 로컬에서 실제 기존 출처를 읽고 검토된 분류 파일을 사용할 수 있습니다. 이 경로 역시 SELECT만 수행하며 테이블을 자동 생성하지 않습니다. 승인 후에는 신규 테이블의 분류를 우선 사용합니다. 실제 서비스 환경에서 분류 파일에 없는 법인을 임의로 업권에 넣는 fallback은 없습니다.

현재 캐시된 실제 OpenDART 자료를 기준으로 승인된 증권 27개 법인의 보수 내역은 2024년 132건, 2025년 135건입니다. 이는 공시 건수이며 업권 전체 인원 수 또는 평균 연봉이 아닙니다.

## 7. 영향·위험과 남은 검증

기존 `/api/search`, `/api/suggest`, `/api/years`, `/rankings`는 유지합니다. 기존 검색 화면의 CSV는 동일한 이스케이프 로직을 공유하는 방식으로 바꿨습니다. 새 업권 URL은 조회만 수행하며 서버 시작 시 마이그레이션을 실행하지 않습니다.

주요 위험은 과거 자료의 회사 식별 부재, 사업 변경에 따른 업권 유효 기간, 상호 변경·동명이인·익명 공개의 오해입니다. 회사명을 키로 일괄 연결하지 않고, 불명확한 분류는 공개하지 않습니다. 새 기업은 자동 탐지하되 분류 근거와 적용 기간이 확정되기 전까지 미분류입니다. 승인된 기업의 신규 연도는 자동 반영됩니다.

초기 업권 데이터는 수백 건 규모이므로 서버에서 승인된 법인의 행을 읽고 15초 캐시 후 정렬·필터·페이지를 계산합니다. 데이터가 커지면 EXPLAIN과 응답 시간을 확인해 DB 집계·페이지 처리를 확대합니다. 기존 출처 테이블에는 salary_id 인덱스가 없으므로 더 큰 데이터에서는 병목이 될 수 있지만 이번 마이그레이션은 그 테이블을 임의 ALTER하지 않습니다.

MySQL DDL은 트랜잭션 롤백 대상이 아니므로 적용 도구는 먼저 원본 두 테이블 및 기존 분류 테이블을 압축 백업합니다. 일부 테이블만 존재하는 상태를 감지하면 자동 복구·삭제하지 않고 중단합니다. 원본 보수 데이터는 수정하지 않습니다.

작업 초반 실제 DB 구조·건수 확인은 성공했습니다. 이후 로컬 서버를 실제 DB에 연결하는 검증과 기본 dry-run은 `ENOTFOUND`(호스트 DNS 해석 오류)로 완료하지 못했습니다. 설정 파일 변경은 확인되지 않았습니다. 현재 검증은 모의 DB HTTP 테스트 및 캐시된 실제 공시 자료의 렌더링을 포함합니다. 운영 DB 변경과 배포, 마이그레이션 SQL의 실제 실행, 최신 실DB 종단 확인은 승인 및 연결 복구 후 수행해야 합니다. AdSense 승인은 보장하지 않습니다.


## 최종 검증

Node 테스트 27개, Python 테스트 8개가 통과했습니다. 캐시된 실제 공시 자료를 사용하는 로컬 HTTP 서버의 2024년 증권 페이지는 HTTP 200이며, 삼성증권 고유번호 00104856·2025년으로 필터한 CSV에는 해당 법인의 5개 행만 포함됐습니다. 최종 코드의 오프라인 마이그레이션 계획과 신규 회사 탐지 도구도 확인했습니다. 운영 DB의 마이그레이션과 배포는 실행하지 않았으며, 실DB 종단 검증은 DNS 오류로 미완료입니다. 브라우저 연결 도구 사용 불가로 시각 검증도 미완료입니다.
