# 20개 업권 확장 결과 (2026-11-14)

증권 전용으로 제한되어 있던 분류와 화면을 20개 업권으로 확장했습니다. 메인 기업 검색과 기업그룹별 페이지는 유지합니다.

## 자료와 분류

- 실제 저장된 2024·2025년 DART 개인별 보수 5,255건에 등장하는 1,286개 법인의 기업개황을 확인했습니다.
- DART 고유번호를 기준으로 932개 법인을 분류했습니다. 종목코드는 보조 식별자이며 회사명으로 합치지 않습니다.
- 불명확하거나 서비스 분류 범위 밖인 354개 법인은 `data/industry-review-queue.json`에 남겼으며 순위에 넣지 않습니다.
- 업종코드와 매핑은 `lib/industry-classifier.js`, 검토된 금융지주 예외는 `data/industry-overrides.json`, 근거와 응답 해시는 `data/industry-companies.json`에서 확인할 수 있습니다.
- 한국표준산업분류를 서비스의 20개 업권으로 묶은 분류입니다. 반도체 제조장비는 반도체, 디스플레이 제조장비는 전자·전기, 화장품은 유통·소비재로 묶습니다. 여러 업권에 걸친 포괄 코드는 제외합니다. 일반 지주회사를 금융업으로 자동 분류하지 않습니다.
- 은행·금융지주에는 금융감독원 명단으로 확인한 비은행 금융지주도 포함합니다. 이름 변경은 동일 DART 법인으로 연결합니다.
- 분류 적용은 2024년 이후입니다. 기존 2021~2023년 자료는 전체 기업 검색에서 유지하며, 검증된 법인 연결 전에는 업권 집계에 넣지 않습니다.
- 이후 연도 자료가 동일 고유번호로 연결되면 기존 조회 서비스가 실제 연도를 자동 노출합니다. 새로운 법인은 분류 근거를 검토해야 합니다.

공식 근거: [DART 기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002), [KSIC 제11차 최종 분류표](https://kostat.go.kr/boardDownload.es?bid=107&list_no=428660&seq=6), [금융감독원 금융지주 명단 보도자료 사본](https://kiri.or.kr/PDF/weeklytrend/20241028/trend20241028_1.pdf).

## 화면과 검증

각 페이지에 접속 즉시 상위 20인, 기업별 현황이 표시됩니다. 연도 선택, 업권 내 이름·회사·직위 검색, 페이지 이동, CSV, 기사 검색 버튼을 동일하게 제공합니다. `/industries` 카드에도 실제 최신 연도와 건수를 표시하고 sitemap에는 20개 페이지를 포함합니다.

- `npm test`: 47개 통과 (메인 검색·자동완성·그룹 페이지 회귀 검증 포함)
- 저장된 실제 자료를 사용하는 로컬 서버: 20개 상세 페이지, 40개 연도별 CSV, 업권 밖 법인 검색 차단, 전체 sitemap 확인 통과
- 운영 DB 연결 없이 `node scripts/migrate-industries.js --plan-only`: 20개 업권 / 932개 법인 / 신규 테이블 4개 계획 확인
- 브라우저 시각 검증은 실행 환경의 브라우저 연결 제약으로 완료하지 못했습니다.

## 적용 방법 — 승인 후 진행

아래 내용은 실행 안내이며 이번 작업에서 운영 DB 변경과 배포는 하지 않았습니다.

1. `app` 폴더에서 `node scripts/migrate-industries.js --plan-only`로 적용 대상을 확인합니다. 이 명령은 운영 DB에 연결하지 않습니다.
2. DB 연결 환경에서 `node scripts/migrate-industries.js`로 읽기 전용 점검을 실행합니다. 원래의 `salary_data`, `salary_dart_sources`를 유지합니다.
3. **사용자 승인 후**, 업권 테이블이 아직 없으면 `node scripts/migrate-industries.js --apply`를 실행합니다. 이미 4개 테이블이 모두 있으면 `node scripts/migrate-industries.js --apply --seed-only`를 사용합니다. 일부만 있으면 스크립트가 중단하므로 먼저 확인해야 합니다.
4. 스크립트는 변경 전 원본·기존 업권 테이블을 `var/backups`에 백업합니다. 신규 업권·법인 분류는 추가하고 기존 업권의 공개 여부를 갱신합니다. 기존에 검토된 법인 분류가 다른 경우 자동 덮어쓰지 않고 중단합니다. 원본 연봉 테이블 변경 여부도 확인합니다. DDL은 자동 롤백되지 않으므로 실패 시 백업과 부분 생성 상태를 확인합니다.
5. 변경 코드를 GitHub에 반영하고 Render에서 해당 커밋을 배포합니다. 자동 배포가 켜져 있으면 push가 배포를 시작하므로 승인 전 push하지 않습니다. `.env`, API 키, 인증서, `var` 자료는 올리지 않습니다.
6. 배포 후 `/industries`와 각 업권 상세 화면에서 2024·2025년, CSV, 기존 메인 검색을 확인합니다. 롤백 시 직전 Render 배포로 되돌릴 수 있습니다. 추가한 테이블을 임의 삭제하거나 원본 DB를 초기화하지 않습니다.

업권 테이블이 없는 환경은 검토된 JSON 파일을 읽는 기존 대체 경로로도 작동합니다. 업권 테이블이 있으면 DB 분류가 우선이므로, 새 코드만 배포하고 DB의 공개 설정·분류를 갱신하지 않으면 이전 범위가 유지됩니다.
